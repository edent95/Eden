CASE #04
Operator vs Provider · Career / Operations

从 B2C Operator 到 B2B Provider：两边都做过以后，我才看懂的事情

从 acquisition、CRM、retention、reactivation 与 operator marketing，转到 provider / B2B 后，重新理解 supplier 与 operator 为什么经常“讲不同语言”。

  • Operator 先问：这对玩家和业务有什么用？
  • Provider 先问：产品如何被采用、上线和放大？
  • 做过 B2C 后，B2B 的需求判断会更接近实际运营。

CASE #05
CRM · Retention · Multi-brand

多品牌 CRM：Retention、Reactivation 和 Promotion Calendar 为什么不能分开看

实际处理多个品牌的 retention / reactivation、CRM、segmentation、VIP journey 与 promotion calendar 时，最大的难点不是“发什么优惠”，而是不同玩家状态与品牌节奏如何一起管理。

  • Retention 和 Reactivation 不是同一个问题。
  • Promotion calendar 需要 central view。
  • 玩家 recency、frequency、value 应该影响沟通，而不是所有人收到同一套 bonus。

CASE #06
Game Provider · RTP · Product Operations

RTP Request：当 Operator 问能不能换 RTP，Provider 端实际上要确认什么？

根据实际碰过的 RTP、demo site 与 operator configuration 工作，把“能不能换 RTP”拆成 available configuration、operator request、market、environment、verification 等层次。

  • RTP 不是前端随手改一个数字。
  • 先确认 provider 实际提供哪些 configuration。
  • Demo、production、market 与 operator setup 都需要区分。

CASE #07
Onboarding · Integration · Currency

Multi-currency Operator Onboarding：为什么开一个 Merchant 不等于已经可以上线

从 merchant / master / agent、currency、demo、operator application 等实际工作，把 operator onboarding 拆成身份、结构、币种、产品、环境与验证。

  • Commercial approval ≠ technical readiness。
  • Currency 是配置问题，也是玩家体验问题。
  • ID hierarchy 不清楚会让 reporting 和 troubleshooting 变得困难。

CASE #08
CRM · Reactivation · Player Lifecycle

从 Dormant 到 Reactivated：我怎样理解 iGaming Reactivation

基于 retention / reactivation 工作经验，把 dormant player、recency、offer、trigger、channel 与 return behaviour 放回完整 lifecycle，而不是把 reactivation 简化成“发更大的 bonus”。

  • 先定义 dormant，才能谈 reactivation。
  • 回来一次不等于长期留存。
  • Offer、timing 与 channel 必须跟 player state 一起看。

CASE #09
Product Operations · Game Launch

Game Lobby Rollout：游戏已经接好了，为什么玩家还是可能看不到？

根据 game lobby、旧线/新线、素材、provider/operator 配置等工作经验，说明 integration complete 和 player-visible launch 中间还有 metadata、placement、currency、market 与 QA。

  • Integrated ≠ visible。
  • Game ID、metadata、asset 与 lobby placement 都可能成为断点。
  • 上线以后还需要 smoke test 与 monitoring。

CASE #10
Analytics · Promotions

Promotion Reporting：高 Turnover 为什么不一定代表活动成功

把 provider promotion、budget、turnover、GGR、玩家参与和后续行为放在同一张表上，避免用单一 vanity metric 判断活动。

  • Turnover 高不代表成本合理。
  • 参与人数高不代表带来增量行为。
  • 活动目标必须在 launch 前定义，reporting 才有意义。

CASE #11
Promotion Technology · Operations

Unique Gift Code：一个看起来很小的 Campaign Feature，为什么会牵动很多系统

从 unique gift code 类需求切入，说明 code generation、eligibility、redemption、reward、expiry、abuse control 与 reporting 如何连接。

  • Marketing idea 最后一定会落到 system rule。
  • 唯一性、重复领取与 expiry 都需要定义。
  • 没有 reporting，就无法知道 code 是否真的产生价值。

CASE #12
B2B · Exhibition · Lead Operations

iGaming 展会不是站 Booth：从会前到会后，真正的 B2B Workflow

根据 SBC Americas、Tbilisi、Manila 等展会相关工作经验，把 event 拆成 pre-event targeting、meeting、qualification、follow-up 与 pipeline，而不是只记录“参加过展会”。

  • 展会前的 target list 比现场随机交换名片更重要。
  • Meeting 本身不是 pipeline。
  • 会后 follow-up 和 qualification 决定 event 是否留下商业价值。
