一眼看懂完整闭环

每一段都有明确反馈；任何一段失败，后面的发布动作都会停止。

你真正会用到的菜单

先选「我要做什么」，复制对应命令到 Eden 仓库终端。

01 / START

开始新任务

从 main 建立独立工作分支。已有未提交内容也会安全保留，不 stash、不 reset。

npm run task:new -- "任务名"
02 / CHECK

只检查，不发布

编译 Wiki、刷新日志索引，然后运行规则、单元测试、TypeScript、production build 与 smoke。

npm run ready
03 / SHIP

完成并发布

先显示文件范围并确认，再自动完成检查、PR、CI、合并、部署与线上验证。

npm run publish -- "标题"

安全不是提醒，是护栏

即使操作错了，分支保护与 required check 仍会挡住不完整发布。

main 始终受保护

正确流程更短，但保护等级没有下降。

禁止直接 push main工作会先进入独立分支与 PR
verify 必须通过规则、测试、类型、构建和产物全部检查
变更必须有日志缺少原因、影响、验证或下一步会失败
部署后检查生产首页、sitemap 与 manifest 必须正常响应

卡住时，看这里

先看失败发生在哪一段，再处理；不要为了赶时间绕过保护。

本地 ready 失败

修复终端里最早出现的错误，再重新运行。失败前不会提交或 push。

npm run ready

想先预览范围

显示当前分支、文件数量与发布计划，不产生任何写入。

npm run publish -- "标题" --dry-run

需要人工审核

等 CI 通过后停在 PR，不自动 merge，也不开始生产部署。

npm run publish -- "标题" --no-merge
