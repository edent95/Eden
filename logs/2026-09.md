### [E-2026-09-10-01] Logging switched to the fleet-wide logbook rag-v1 format

- **type**: `docs`
- **scope**: `config`
- **impact**: `cross-cutting`
- **changed**:
  - `AGENTS.md` section 4 — rewritten to the rag-v1 rules shared by the other projects:
    `## YYYY-MM-DD` day heading + `### [E-…]` entries, seven fields, `ripples` three questions,
    and the three hard rules (append via script / oldest→newest / day headings written by the script).
  - `scripts/append-log.mjs` (new) — the portable O_APPEND appender used across all projects.
  - `scripts/harness/log-append.mjs` (new) — Eden-specific wrapper that points the generic
    appender at `logs/<current MYT month>.md` instead of the root `log.md`, creating the month
    file if it does not exist yet.
  - `scripts/harness/check-log.mjs` — the evidence gate now accepts **either** rag-v1
    (`changed` / `ripples` / `verified` / `impact` / `keywords`) **or** the pre-2026-09
    five-field Chinese shape (改动 / 原因 / 影响 / 验证 / 后续).
  - `package.json` — added `log:append` and `log:check`.
  - `log.md` — frontmatter now declares `log_format: rag-v1`.
- **ripples**:
  - **The month file is chosen with `Asia/Kuala_Lumpur`, matching `check-log.mjs`.** Anyone who
    changes the timezone in one of the two files must change it in the other: on the first or
    last day of a month the appender would write into one month's file while the gate inspects
    another, and `verify:log` would fail with "Project files changed without a matching log".
  - **`npm run log:append` must NOT be pointed at the root `log.md`.** That file is a stable
    pointer to the monthly archive; writing entries there bypasses `logs/` and makes
    `verify:log` fail. The wrapper exists precisely to prevent that.
  - **Existing history in `logs/2026-04..09.md` is NOT backfilled.** Both entry shapes now
    coexist, so anything that parses these files must not assume every entry has `ripples`.
  - **`logs/index.md` still has to be regenerated** with `npm run log:index` after appending —
    the gate checks it separately, and the appender does not do it.
- **verified**:
  - This entry itself was written with `npm run log:append`, which created the `## 2026-09-10`
    day heading in `logs/2026-09.md` automatically.
  - `npm run log:check` passes: no duplicate IDs, day headings ascend oldest → newest.
  - `npm run verify:log` green after `npm run log:index`.
- **keywords**: logbook, rag-v1, log:append, O_APPEND, monthly log, logs/index.md, check-log,
  Asia/Kuala_Lumpur, day heading, ripples, change-log gate
