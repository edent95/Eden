### [E-2026-11-10-164143-c052] CI:修 M1 自托管 runner 被 IndexNow 的 sparse checkout 污染，之后所有 PR 的 verify 都只 checkout 出 scripts/seo

- type: fix
- scope: .github/workflows/verify.yml、.github/workflows/deploy.yml(M1 自托管 runner 共用工作目录)
- impact: PR #139 在 deploy.yml 加的「Checkout IndexNow script」用 sparse-checkout: scripts/seo。自托管 runner 各 job 共用 _work/Eden/Eden,actions/checkout 把 core.sparseCheckout=true 留在 .git/config;之后的 checkout 虽然跑了 sparse-checkout disable,但随后又 unset extensions.worktreeConfig,写进 config.worktree 的 false 失效，工作区只剩 scripts/seo。结果：2026-11-10 起 PR #140 的 verify 连续三次在 Setup Node 报「Dependencies lock file is not found」,下一次 main 部署的 build 也会挂。
- changed: verify.yml 与 deploy.yml 在每个 Checkout 前加「Reset leftover sparse checkout」(仅 self-hosted:unset core.sparseCheckout / core.sparseCheckoutCone,删 .git/info/sparse-checkout);deploy.yml 的 IndexNow checkout 改成完整 checkout，不再 sparse。
- ripples: (1) 自托管 runner 上任何 job 都不要用 actions/checkout 的 sparse-checkout(包括别的仓库);要省时间就用 path: 单独目录。(2) 本修复 PR 自己的 verify 会先跑清理步骤，顺带把 M1 上已被污染的工作目录修好;合并后 #140 等被卡的 PR 重跑即可。(3) 本机复现：被污染状态下照 actions/checkout 的顺序 disable + unset extensions.worktreeConfig + checkout --force,工作区仍只剩 scripts;先跑清理步骤后完整恢复。
- verified: 本机用临时仓库复现被污染状态并验证清理步骤有效;npm run check 全部门禁通过;修复 PR 的 verify 在 M1 上通过即证明清理生效。
- keywords: ci, github actions, self-hosted runner, m1, sparse-checkout, actions/checkout, indexnow, deploy, verify, lock file not found
