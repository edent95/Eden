## 2026-09-28 — Eden 日志改成「一条一个文件」(logs/entries/),并行 PR 不再在月度 log 上冲突

### [E-2026-09-28-190914-889d] Eden 日志改成「一条一个文件」(logs/entries/),并行 PR 不再在月度 log 上冲突
- **type**: `chore`
- **scope**: `scripts/harness/log-append.mjs`、`scripts/harness/check-log.mjs`、`scripts/harness/build-log-index.mjs`、`logs/entries/README.md`、`logs/index.md`、`AGENTS.md`、`CLAUDE.md`、`log.md`、`state/current.md`、`docs/operator-workflow.md`
- **impact**: `cross-cutting` —— 每个改 Eden 的 agent / 分支写日志的方式都变了。
- **changed**:
  - Eden `npm run log:append` 不再往当月 `logs/YYYY-MM.md` 末尾追加,改为用 `wx` 新建 `logs/entries/<YYYY-MM-DD>-<HHMMSS>-<4 位十六进制>.md`,内容是 `## 日期 — 标题` + `### [E-<日期>-<时分秒>-<随机>] 标题`;日期时间按 Asia/Kuala_Lumpur,ID 是时间 + 随机,不再按「当天最大序号 +1」。
  - Eden `check-log.mjs`(`verify:log`):改动的项目文件配上至少一个新的 `logs/entries/` 条目文件即放行,检查整份条目文件的 rag-v1 字段与 `## YYYY-MM-DD` 天标题;走条目文件时不再要求 `logs/index.md` 变化。老路径(追加当月文件 + `log:index`)仍认。
  - Eden `log:check`:当月文件照旧交给通用 `scripts/append-log.mjs --check`,另查条目文件的天标题、文件名日期、与月度文件之间的 ID 重号。
  - Eden `build-log-index.mjs`:`logs/index.md` 仍只由月度文件生成,顶部加一段固定说明指向 `logs/entries/`。
  - AGENTS.md §4、CLAUDE.md「Logging is a build gate」、`log.md` 指针、`state/current.md`、`docs/operator-workflow.md` 改成新规则。
- **ripples**:
  - 以后任何人往 `logs/2026-*.md` 月度文件追加条目,都会重新制造 PR 冲突 —— 月度文件与 `logs/index.md` 现在是冻结历史。
  - `logs/index.md` 不列条目文件(否则每个 PR 都改它又冲突);找最近改动要 `ls logs/entries | tail -20`。改 `build-log-index.mjs` 时别把条目文件加回索引。
  - personal-dashboard 扫描器靠文件名 `^\d{4}-\d{2}-\d{2}-.+\.md$` 与 `## 日期` 认条目:改名或删天标题会让条目从面板静默消失;`logs/` 不能 gitignore。
  - Eden 的 `scripts/append-log.mjs`(通用脚本旧版)现在只被 `log:check` 用来查月度文件。
- **verified**: `npm run log:check`、`npm run check` 通过;本条就是用新的 `npm run log:append` 写出来的。
