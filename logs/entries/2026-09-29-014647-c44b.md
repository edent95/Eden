### [E-2026-09-29-014647-c44b] publish 端到端测试后的三处修正:ready 按分支判日志门禁、派生文件过期时拦下、状态行首列不再被吃
- **type**: fix
- **scope**: scripts/workflow/publish.mjs, scripts/workflow/lib.mjs, tests/unit/workflow-utils.test.ts
- **impact**: 在沙盒(临时 clone + 本地 bare origin + 假 gh)里把 PR #63 的新 publish 流程六个场景跑了一遍,修掉三处会让人白跑或白开 PR 的问题。
- **changed**: publish 调 `npm run ready` 时带 `HARNESS_BASE_REF=origin/<默认分支>`(已设则沿用),日志门禁和 CI 一样按整个分支判,分支上已提交的日志条目算数;新增 `staleDerived()` + `DERIVED_SOURCES`:派生文件(`generated/content.ts` ← `wiki/`,`logs/index.md` ← `logs/YYYY-MM.md`)在 ready 前就有未暂存改动、而这次又暂存了它的源文件时,提交前停下并提示 `git diff` / `git add`;`command()` 新增 `raw` 选项,`statusLines()` 用它保留 `git status --short` 首行的行首空格;在默认分支上有未推送提交时先于「没暂存」报出(dry-run 也报)。
- **ripples**: 在任务分支上只推已有提交(不再新暂存)时,工作区里别人的未暂存改动不再让 ready 以「没有日志条目」失败 —— 前提是分支上已有条目;若本地 origin/<默认分支> 没 fetch 过,ready 的门禁比较基准是旧的(publish 自己在 ready 前 fetch,不受影响)。派生文件事先脏又动了源文件的,现在 publish 会停下要人手动 `git add` 派生文件,不再推出一个 CI 必红的 PR。ready 仍会用当前工作区重写派生文件,事先对它们的手改会被覆盖(本来就是生成文件)。
- **verified**: 沙盒 e2e:main 上暂存 + 未暂存 + 未跟踪 → 开 `fix/20260929-…` 分支、提交只含暂存文件与干净派生文件、推到沙盒 origin、`gh pr create` 无 merge;没暂存 → 退出 1 且列改动与 `git add` 提示;本地 main 有未推送提交 → 拒绝、提交保留;任务分支复用 / 新建 PR;`--merge` 走 checks → merge → deploy → live;未知参数被拒;派生文件事先脏 → 不自动暂存(修后改为拦下,`git add` 后重跑通过)。`node --experimental-strip-types --test tests/unit/workflow-utils.test.ts` 10/10;`HARNESS_BASE_REF=origin/main npm run check` 通过。
