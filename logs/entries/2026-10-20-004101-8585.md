## 2026-10-20 — 部署在 M1 上打包 Pages 产物失败(macOS 没有 gtar):改用系统 tar + upload-artifact

### [E-2026-10-20-004101-8585] 部署在 M1 上打包 Pages 产物失败(macOS 没有 gtar):改用系统 tar + upload-artifact

- type: fix
- scope: .github/workflows/deploy.yml 的 build job
- impact: #113 把部署改跑 M1 后，第一次部署 `npm run check` 通过，但 actions/upload-pages-artifact@v3 的「Archive artifact」在 macOS 上调用 GNU `gtar`,M1 没装，exit 127,Pages 没更新(#112 的 /life-os 改动因此没上线)。现在自己用系统 tar 打成 artifact.tar,再用 actions/upload-artifact@v4 以 `github-pages` 名上传，deploy-pages 照旧读它。
- changed: .github/workflows/deploy.yml(「Upload Pages artifact」拆成「Archive Pages artifact」`tar -C dist -chf $RUNNER_TEMP/artifact.tar --exclude=.git --exclude=.github .` + upload-artifact@v4,name github-pages、retention-days 1、if-no-files-found error)
- ripples: (1) 这两步就是 upload-pages-artifact 内部做的事，在 Linux 和 macOS 上都能跑;以后换回 ubuntu-latest 不用改回去。(2) 没有在 M1 上 brew install gnu-tar:M1 上 brew 装包曾把 node@22 弄坏(通用知识 2026-10-12)。别的仓库在 M1 上部署 Pages 时会遇到同样问题，照这一条改。(3) artifact 名必须叫 github-pages,里面必须是一个 artifact.tar,否则 deploy-pages 找不到。
- verified: 本机(macOS)用同一条 tar 命令打包 dist 成功;npm run check 全过;合并后 main 上的 Deploy to GitHub Pages 在 m1-Eden 上跑通，线上 /life-os 出现新文案
- keywords: GitHub Pages, upload-pages-artifact, gtar, GNU tar, macOS, self-hosted runner, M1, exit 127, deploy.yml, artifact.tar, deploy-pages
