### [E-2026-11-10-232848-2029] Service worker:开发 / 预览服务器不再注册(并注销旧的);离线缓存没命中时回 Response.error(),不再报 Failed to convert value to 'Response'

- type: fix
- scope: index.tsx 的 service worker 注册、public/sw.js 的 fetch 兜底
- impact: 用户 2026-11-10 贴来控制台：worktree 预览(localhost:56471)在 PR 合并、预览停掉后，页面只剩一串 sw.js「Uncaught (in promise) TypeError: Failed to convert value to 'Response'」与 ERR_FAILED。原因两层:(1) index.tsx 在 vite dev 也注册 sw.js,预览端口上的 worker 在服务停掉后继续拦请求;(2) sw.js 的兜底 `caches.match()` 没命中时得到 undefined,交给 respondWith() 就是这个报错——正式站离线访问没缓存过的页面也会这样。
- changed: index.tsx 只在 import.meta.env.PROD 注册 worker,开发环境启动时注销本源已有的 worker;public/sw.js 导航请求与普通请求的离线兜底在缓存没命中时回 Response.error()。
- ripples: (1) 已经被旧 worker 控制的死端口(例如 56471)这次修不到——服务已停，新代码加载不进来;对那个标签页：关掉，或 DevTools → Application → Service workers → Unregister。之后起的新预览不会再注册 worker。(2) 正式站行为不变：在线时照旧，离线且没缓存时现在显示浏览器自己的离线页，而不是报错。(3) 想在本地测 worker,用 `npm run build && npm run preview`(PROD 构建)。
- verified: npm run check 全部门禁通过(含 dist/sw.js 冒烟);代码检查确认 respondWith 的两个兜底分支都返回 Response。
